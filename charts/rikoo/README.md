# rikoo

Helm chart of Rikoo, the control platform for AI agents in production: api, worker, migrations,
parsing sidecar, embedded MCP sandbox, and optional bundled PostgreSQL (pgvector), Redis and MinIO.

## Quick start

```bash
helm dependency update .
helm install rikoo . -n rikoo --create-namespace \
  -f ../../examples/minimal-installation/values.yaml --set rikoo.image.tag=vX.Y.Z
```

The vault sealing pair is required and never generated by the chart: see `rikoo.secrets.sealing`
in `values.yaml` and `examples/minimal-installation`.

## Values

Every key is documented in place in [`values.yaml`](./values.yaml). Structure:

| Section                    | What it configures                                                                                  |
| -------------------------- | --------------------------------------------------------------------------------------------------- |
| `rikoo.*`                  | Product settings shared by api and worker: origin, logging, locale, licence, feature flags, secrets, egress policy, attachments, SMTP, OTEL |
| `rikoo.image`              | Registry, tag (required), pull policy and pull secrets of the four Rikoo images                     |
| `rikoo.api` / `rikoo.worker` | Per-component image, replicas, resources, probes, HPA / KEDA, PDB, ServiceMonitor, extra settings |
| `rikoo.migrations`         | The Prisma migrations Job (post-install, pre-upgrade)                                               |
| `rikoo.sidecarParsing`     | The optional PDF/Office parsing service                                                             |
| `rikoo.sandbox`            | The embedded MCP sandbox: core, egress proxy, Playwright, workspace storage                          |
| `rikoo.networkPolicy`      | The NetworkPolicies isolating the sandbox                                                            |
| `rikoo.ingress`            | The ingress in front of the api                                                                     |
| `postgresql` / `redis` / `s3` | Bundled store (`deploy: true`) or external one; sub-chart values passed through                  |

## Resources rendered

api and worker `Deployment`, `Service`, `PodDisruptionBudget` (optional `HorizontalPodAutoscaler`,
`ScaledObject`, `ServiceMonitor`); migrations `Job` (Helm hook); sidecar `Deployment` + `Service`;
sandbox core / egress / Playwright `Deployment` + `Service`, optional `PersistentVolumeClaim`,
three `NetworkPolicy`; one `ServiceAccount` (no API access, token not mounted); a `ConfigMap` of
non-secret settings; chart-managed `Secret`s for generated credentials; optional `Ingress`.
